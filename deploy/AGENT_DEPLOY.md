# Выкатка neurolegal — регламент для агента

Человеческая версия — `RELEASE.md` в корне репозитория: она остаётся
источником истины по шагам. Здесь то же самое для агента: что проверять, где
отказ законен, а где надо остановиться и спросить человека.

Инфраструктура и разбор аварий — `docs/runbooks/deploy.md` (локальный, вне git).

Скилл `.claude/skills/deploying-neurolegal/SKILL.md` — тонкая ссылка на этот
файл: `.claude/` в `.gitignore`, поэтому регламент живёт здесь.

## Что происходит при выкатке

Push тега `v*` запускает CI (~4 минуты). Зелёный прогон пушит метку
`refs/ci-passed/<коммит>`, затем джоба `deploy` по SSH запускает
`deploy/github_remote.sh` → `deploy/deploy.sh`. Без метки выкатка не
начинается. Реестра образов нет: образ собирается на самой VM. Секреты и
первый провижининг — `deploy/CD.md`.

`deploy.sh` едет вместе с кодом, поэтому **работает версия скрипта с текущего
задеплоенного тега**. Релиз, меняющий сам скрипт, идёт ещё старой версией — его
новые проверки включатся со следующей выкатки. Признак: в выводе нет строки
`==> гейт CI`.

## Последовательность

```bash
ssh yasa-vm 'cd /srv/neurolegal && git describe --tags && docker compose ps'
```

Прод должен быть здоров **до** релиза: поверх сломанного не выкатывают.

```bash
git checkout main && git pull && git tag vX.Y.Z -m "что изменилось" && git push origin main --tags
```

```bash
gh run watch "$(gh run list --workflow=ci.yml --limit 1 --json databaseId --jq '.[0].databaseId')" --exit-status
```

Дождаться, пока job `deploy` станет зелёной. Ручной запасной путь:

```bash
make deploy TAG=vX.Y.Z
```

Проверка: `https://yasa-tech.ru` → 200 и `ssl_verify_result: 0`,
`https://admin.yasa-tech.ru` → 401, четыре сервиса healthy (agent, rag,
documents, templates — с E20), `make deploy-history` показывает свежую
строку. Ответ в чате глазами проверяет человек — там авторизация.

С E20 в `.env.prod` нужен `NEUROLEGAL_TEMPLATES_BASE_URL=http://templates:8003`
(агент и RAG-прокси ходят в templates-сервис по имени compose-сервиса);
`NEUROLEGAL_REQUIRE_INTERNAL_TOKEN=true` теперь роняет на старте и
templates-сервис, если общий токен не задан.

## Вердикты гейта

| Вердикт | Значение | Действие |
|---|---|---|
| `passed` | метка есть, тег на `main` | выкатка идёт |
| `rollback` | цель — предок работающей версии | идёт без метки, так задумано |
| `bypassed` | `ALLOW_UNVERIFIED=1` | законно только при недоступном GitHub |
| `blocked` | код 3, сервер не тронут | разобраться, не повторять вслепую |

## Отказы

| Сообщение | Причина и лечение |
|---|---|
| `нет отметки CI на коммите тега` | прогон идёт или красный. Дождаться; прогона не было — `gh workflow run ci.yml --ref vX.Y.Z` |
| `коммит тега не принадлежит origin/main` | тег не с `main`. Слить ветку, выпустить новый номер — не переставлять тег |
| `тег … не найден` | забыт `git push --tags` |
| `corpus/manifest.yaml изменён на сервере` | правки из админки. Закоммитить или отбросить командой из вывода |
| `в rag выполняется ingest-джоб` | ждать. Прерывание оставит прод без поисковых индексов |
| `нет tessdata` / права | выполнить на сервере команды из вывода скрипта |
| `/healthz` красный | сначала откатиться командой из вывода, потом разбираться |

## Откат

```bash
make deploy TAG=<предыдущий тег>
```

Гейт откату не мешает никогда. **База назад не едет** — все `downgrade()`
деструктивны, миграции аддитивные, предыдущий код работает поверх новой схемы.

## Запрещено

- **Обходить гейт, чтобы «не ждать».** `ALLOW_UNVERIFIED=1` — только когда
  GitHub недоступен. Красный CI и идущий прогон обходом не лечатся.
- **Править файлы на сервере.** Он read-only копия тега.
- **Откатывать миграции.** Это потеря данных.
- **Переставлять опубликованные теги** (`git tag -f`, force-push).
- **Повторять выкатку в цикле, ожидая метку.** Дождаться прогона, потом одна
  команда.
- **Выкатывать без спроса.** Прод трогают по явной просьбе человека; отказ
  гейта — повод доложить, а не обойти.

## Красные флаги

Мысли, на которых надо остановиться:

- «CI всё равно зелёный локально, обойду гейт» — локальный `make check` не
  гоняет интеграционные тесты и обе сборки фронта.
- «Откачу базу заодно» — нет.
- «Поправлю прямо на сервере, потом закоммичу» — нет.
- «Тег не на main, но код тот же» — выпустить новый номер.
