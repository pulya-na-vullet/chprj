# Neurolegal → полноценный AI-ассистент юриста: продуктовое исследование

Дата: 2026-07-05.
Метод: deep-research (5 поисковых направлений, 22 источника, 109 утверждений,
25 прошли адверсариальную проверку: 13 подтверждено 3/3, 1 опровергнуто,
остальные собраны с цитатами, но не успели пройти верификацию — помечены ⚠).
Продолжает `agent-research-2026-06-28.md` и `neuro-lawyer-upgrade-2026-06-28.md`.

## 1. Резюме

Гипотеза пользователя подтверждается рынком: **поиск по законам сам по себе не
продукт** — у клиентов есть Гарант/КонсультантПлюс, а конкуренты уже строят
не «чат по кодексам», а рабочее пространство юриста. Ядро ценности во всех
ориентирах одно и то же, и оно совпадает с тем, чего у neurolegal нет:

1. **Работа с документами пользователя** (загрузка → анализ → риски → отчёт) —
   это фича №1 и у Нейроюриста, и у Legora/Harvey/Spellbook, и №1 use case
   по опросам юристов (document review 74%, research 73%, summarization 72% ⚠).
2. **Судебная практика как источник** — у Нейроюриста практика доминирует
   корпус на порядки (2,5 млн текстов практики по ЗПП против 6 тыс. текстов
   законодательства по корпправу — подтверждено 3/3).
3. **Workflow/playbook-слой** — именованные повторяемые задачи («анализ
   договора», «ответ на претензию»), а не свободный чат. У Harvey это
   отдельный продуктовый примитив (подтверждено 3/3).

Приоритет для теста на реальных клиентах: **P0 — загрузка документа + проверка
договора на риски с привязкой к нормам** (уникальное преимущество neurolegal:
риск-отчёт, где каждый риск процитирован и из договора, и из статьи кодекса),
затем P1 — судебная практика (арбитраж) и режим «команд».

## 2. Карта фич конкурентов

### Яндекс Нейроюрист (главный РФ-ориентир)

Подтверждено (3/3 голосов, первоисточники neurolegal.ya.ru, yandex.ru/company, habr):

- Заключения со ссылками на **нормы права и судебную практику**.
- **Загрузка файлов 20+ форматов** (PDF/DOCX/XLSX/PPTX/изображения/аудио/видео),
  включая **сканы PDF**; анализ договоров с оценкой рисков; сравнение документов.
- Источники: нормативка, судебные решения, материалы СПС **Гарант**
  (доступ к СПС — опция +3 000 ₽/мес), файлы пользователя, интернет (по выбору).
- Встроенные ИИ-агенты: анализ договоров, сравнение версий с подсветкой
  изменений и комментариями, упрощение юртекста. Отрасли: трудовое,
  корпоративное, информационное, обязательственное, рекламное право, ЗПП, ИС.
- Корпус — миллионы документов: Конституция, ФЗ, подзаконные акты, приказы
  ведомств, письма министерств/служб, постановления Правительства + практика;
  сегментация по сферам права с фильтрацией.

⚠ Не прошло верификацию (лимит сессии), но извлечено с цитатами:

- RAG подаёт модели **топ-50 документов** (не топ-5/10); семейство векторных
  индексов вместо одного с пост-фильтрацией; иерархия источников зашита в
  ранжирование (пленумы ВС выше нижестоящих судов).
- Апрель 2026 — «Подбор судебной практики»: семантический поиск решений по
  свободному описанию обстоятельств, до 20 актов с объяснением релевантности,
  с учётом иерархии судов (заявлено: 30–90 мин → 5–10 мин).
- Июнь 2026 — «Ответ на претензию»: черновик за 3–10 мин на основе «умной
  папки» с примерами ответов компании (кейс МегаФона: −50% времени).
- Декабрь 2025 — «Анализ рисков по НДС 2026»: пакетная проверка до 10
  договоров (включая сканы), сводная таблица формулировок + заключение.
- Метрики/цены: «до 40% задач юриста», 86% положительных оценок, до 999 файлов
  на проект; 20 бесплатных запросов/мес, тарифы 2 000/6 000/8 500 ₽/мес
  (50/200/400 запросов), Yandex Cloud marketplace + on-premises.
- Опровергнуто (0/3): формулировка про «ровно восемь готовых команд» — набор
  команд другой/меняется, не опираться.

Подтверждено: юристы **создают кастомных агентов-workflow на естественном
языке**, привязанных к шаблонам и экспертизе фирмы; к агенту прикрепляются

⚠: Vault до 100k документов; кейсы — сводки по договорам аренды 3–4 часа →

## 3. Что говорит практика (риски продукта)

- ⚠ Stanford HAI: даже коммерческие RAG-инструменты галлюцинируют —
  Lexis+ AI ~17%, Westlaw AI-AR ~33%; отдельный failure mode —
  **misgrounding**: верный ответ с цитатой, которая его не подтверждает.
  Наличие цитаты ≠ качество. Это прямо поддерживает пункт «citation validator»
  из `agent-research-2026-06-28.md` — он же становится маркетинговым
  преимуществом («каждое утверждение проверено против извлечённого текста»).
- ⚠ ContractEval (arXiv 2508.03080): лучшие LLM на clause-level risk — уровень
  «junior legal assistant», F1 ~0.64; главный failure mode — ложное «риска
  нет» (>30% false negatives у слабых моделей). Вывод: проверка договора
  должна быть **checklist-driven** (каждый пункт плейбука явно закрыт:
  найдено/отсутствует/не применимо), а не «спроси модель что не так»,
  и позиционироваться как first-pass review с подписью юриста.
- ⚠ GraphRAG-исследование по EPC-контрактам: naive chunk-RAG дал **ноль**
  прироста точности риск-классификации против LLM без ретрива; структурная
  привязка (таксономия рисков, разметка по клаузам) — дала. Пайплайн должен
  опираться на структуру договора и правила, не на «похожие чанки».
- ⚠ Box AI production-пайплайн: OCR → chunk re-ranking → CoT + JSON-schema
  extraction → **LLM-judge с retry** — 82% success в проде; structured output
  через tool calling ощутимо поднимает точность извлечения.

## 4. Gap-анализ neurolegal

Есть сейчас: чат-агент с intent-роутингом, rag_search/fetch_article/list_acts
по кодексам (DOCX), citations как события, фильтр по актам, web_search как
контекст, ретрив-бенчмарк, админка корпуса. Нет: загрузки файлов (композер
принимает только текст), любой работы с документами пользователя, судебной
практики, подзаконки, workflow-слоя, drafting, сравнения документов, экспорта.

| Приоритет | Функция | Почему |
|---|---|---|
| **P0** | Загрузка документа (DOCX, потом PDF) + «чат с документом» | Порог входа в категорию; фича №1 у всех конкурентов |
| **P0** | Проверка договора на риски по плейбуку + отчёт с двойным цитированием (пункт договора ↔ статья закона) | Именно это просил пользователь; дифференциатор против Гарант/К+ |
| **P1** | Судебная практика (старт: арбитраж, kad.arbitr через API-посредника) как отдельный namespace | Крупнейший data-gap; «подбор практики по обстоятельствам» — задача, которую юристы делают часами |
| **P1** | Команды/workflows в UI (анализ договора, ответ на претензию, подбор практики) вместо чистого чата | Паттерн всех трёх ориентиров; упаковка end-to-end задач |
| **P1** | Сравнение двух версий документа с комментариями | Есть у Нейроюриста и Legora; технически дешёво поверх P0-парсера |
| **P2** | Drafting: ответ на претензию / типовые документы на «умной папке» примеров | Сильный кейс Нейроюриста; требует загрузку + шаблоны |
| **P2** | Tabular Review по документам пользователя (пакетная проверка N договоров) | У вас уже есть UI-паттерн для источников права |
| **P2** | Due diligence контрагента (ЕГРЮЛ + ЕФРСБ + арбитражные дела по ИНН) | Отдельный источник ценности; ждёт интеграций из §6 |
| **P2** | Подзаконные акты, письма ФНС/Минфина в корпус | По плану из research-2026-06-28 (publication.pravo.gov.ru) |
| **P3** | Word add-in, redline-экспорт (.docx tracked changes) | Стандарт западных продуктов; для MVP хватит отчёта в UI + экспорт |

Инфраструктура качества (из аудита 28.06, теперь подтверждена рынком):
citation validator против articles_seen, answer contract, расширение gold set —
делать параллельно с P0, это защита от misgrounding.

## 5. Пайплайн «загрузка файла → проверка договора на риски»

Рекомендуемая архитектура (по мотивам ContractEval, Box AI, GraphRAG-выводов,
openreview-cli/LexReviewer):

1. **Upload**: `POST /documents` на агент-сервисе (multipart), хранение в
   Postgres (таблица `user_documents`, agent-owned). MVP — только DOCX
   (python-docx уже в стеке); PDF-сканы (OCR) — вторая итерация, это заметный
   отдельный проект.
2. **Парсинг в дерево секций**, не в плоский текст: иерархия
   раздел → пункт → подпункт с нумерацией и span-координатами, чтобы каждый
   вывод отчёта ссылался на конкретный пункт договора. Это новый парсер
   (структура договора ≠ структура кодекса), но идиомы `parsing/docx.py`
   переиспользуемы.
3. **Плейбук = YAML-набор правил** (аналогия с `manifest.yaml`):
   тип договора (поставка/услуги/аренда/НДА), список проверок; у каждой —
   id, название клаузы, anchor-паттерны, вопрос к LLM, уровень риска,
   норма-подсказка (какие статьи проверять через rag_search). Старт: 1–2
   типа договора × 15–25 правил, написанных с юристом-консультантом.
4. **Матчинг клауз — ступенчато**: детерминированные якоря → hybrid retrieval
   по секциям документа → LLM-классификация со structured output
   (JSON schema через tool calling). Малая модель для классификации клауз,
   большая — для риск-выводов.
5. **Каждое правило плейбука закрывается явно**: found / missing / not
   applicable. «Missing» — это тоже риск (нет предела ответственности, нет
   порядка расторжения). Никогда не полагаться на «модель сама заметит».
6. **Граундинг в право**: для сработавших правил — существующий `rag_search`
   (+ фильтр по актам) достаёт статьи; в отчёте риск = цитата из договора
   (пункт N) + норма («ст. N ГК РФ») + пояснение + рекомендация правки.
   Citation validator проверяет каждую «ст. N» против извлечённого.
7. **Верификация**: LLM-judge пас по каждому найденному риску
   (подтверждён/сомнителен) с одним retry — дёшево и заметно поднимает
   точность (Box: 80.5% против 73.3% у самого экстрактора).
8. **Отчёт**: сводная таблица рисков по уровням + карта покрытия плейбука
   (сколько правил проверено/найдено/отсутствует) в UI; экспорт .docx —
   позже (есть open-source referenсe: legal-redline-tools).
9. **Позиционирование в UI**: «черновая проверка, требует подтверждения
   юриста» — и это честно (см. §3), и снижает риск продукта.

Оценка: MVP (DOCX + 1 тип договора + отчёт в чат-UI) — это цельный слайс
через весь стек: contracts DTO → upload route → parser → playbook engine →
две LLM-стадии → SSE-события отчёта → фронт.

Порядок подключения: (1) pravo.gov.ru — актуальность корпуса НПА;
(2) kad.arbitr через wrapper — судебная практика для P1 (пилот: 2–3 категории
споров, не «вся практика»); (3) ЕФРСБ + ЕГРЮЛ — при выходе на DD-сценарий.
Практику держать в отдельном namespace с собственным цитатным форматом
(дело № …), никогда не смешивая со статутными цитатами — как решено 28.06.

## 7. Ценовой контекст (⚠)

Нейроюрист: 2 000–8 500 ₽/мес за место + 3 000 ₽/мес за доступ к СПС;
20 запросов/мес бесплатно. Legora ≈ $3k/место/год (мин. 10 мест),
Harvey ≈ $40k/год за 10 мест. Для теста на клиентах РФ вилка Нейроюриста —
разумный якорь.
